LANagrafica

A web application that helps Italian non-profit associations (ODV, APS, ETS) digitalize and manage their member registry in compliance with the Codice del Terzo Settore.

It handles member onboarding, membership card generation, document management and email notifications, with an admin-facing HTML template editor that lets each association customize its notification and document templates without code changes. The platform is multi-tenant: multiple independent associations run on the same shared infrastructure, each fully isolated with its own data and configuration.

Architectural Highlights

  1. GitOps Delivery

    Pushing a release branch triggers a pipeline that builds Docker images and updates Helm values. ArgoCD automatically rolls out the new version.

  2. Secrets Automation

    Sensitive values are stored in Bitwarden Secrets Manager and never written to the repository. A Kubernetes operator reconciles CRDs into native Kubernetes Secrets.

  3. Centralised Observability

    Promtail collects logs from all tenant workloads and forwards them to Loki. Grafana provides a single pane of glass for querying and visualising logs.

Roadmap

What's Next

  1. Linkerd service mesh

    Automatic mTLS encryption for all inter-service traffic.

  2. Async messaging

    Kafka or equivalent, to decouple long-running operations such as email dispatch and document generation from the synchronous request path.

  3. Multi-channel notifications

    Extend beyond email to SMS and other channels.

  4. Inventory & order tracking

    Let an association manage its own stock and member orders alongside the registry.

  5. Perses as dashboards-as-code

    Evaluating Perses as a Kubernetes-native, GitOps-friendly alternative to Grafana for operational dashboards.

Workflow

Development Workflow

LANagrafica started in 2022 as a learning side project. In the past few months, development has adopted an agentic workflow built on a custom Claude Code plugin: changes go through spec-driven development (SDD), meaning a written spec, a generated plan broken into discrete tasks, then task-by-task execution and review, with each run's artifacts kept in the relevant repo.

The plugin also packages the team's domain and stack knowledge (the app's business rules, frontend, backend and DevOps conventions) as reusable skills, so planning and execution stay consistent with how the platform actually works.
